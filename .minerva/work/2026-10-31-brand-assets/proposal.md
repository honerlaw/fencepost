# Proposal: brand-assets

**Date**: 2026-10-31
**Status**: Shipped (2026-10-31)

## Goal
Every place the app shows an icon or logo shows the Fencepost "Picket F" mark instead of the Expo and React Native defaults: the iOS app icon (an Icon Composer bundle on the chalkboard), the Android adaptive icon (chalkboard background), the splash screen (board color and ink following the system scheme), the web favicon, and the in-app title in the topics sheet. The theme palette the mark is drawn from is documented in README and kept in sync with `app.json` and the README by a test, and every raster asset can be regenerated from one geometry module and that palette with one command.

## Why
The request, verbatim, after three logo candidates were shown on an artifact page (A posts-and-rails, B picket F, C marker sketch), each as an icon on blue, whiteboard and chalkboard tiles:

> "B chalkboard variation, can we make sure to update the theme and document the theme colors and such if we have not already, go ahead and also replace and update logos / splash / etc"

Facts verified at intake:

- The palette lives in `src/theme/colors.ts` (`lightColors`/`darkColors`: board, dot, card, ink, muted, rule, wash, blue, blueWash, red, redWash, green, greenWash, gold, goldInk, goldWash) and feeds `tamagui.config.ts`. It is framework-free by design. Fonts: Bricolage Grotesque (display), Atkinson Hyperlegible (body), JetBrains Mono (code), Kalam (marker). The colors file's header cites "the design spec", which is not in the repo. README has no theme or brand section; `.minerva/reference/` is empty.
- In-app there is no Expo artwork; the app name is text in the topics sheet title and the welcome card eyebrow.
- Mark B geometry (1024 viewBox): top rail `rect x=300 y=356 w=440 h=96 rx=48` (ink), lower rail `rect x=300 y=548 w=360 h=96 rx=48` (accent), picket `M300 312 L364 228 L428 312 V752 a44 44 0 0 1 -44 44 H344 a44 44 0 0 1 -44 -44 Z` (ink). ## Approach
One work unit, one PR, unphased. What shipped:

1. **One geometry source.** `src/theme/brand-mark.ts` exports the mark's three shapes and the 1024 viewBox as plain constants. `src/components/ui/brand-mark.tsx` draws them in-app and `scripts/brand/` derives every asset from them.
2. **Renderer** under `scripts/brand/`: `svg.ts` (shape, document, scale and tile helpers), `targets.ts` (the raster and vector target lists, with `ICON_TILE` shared by `icon.png` and `icon.svg`), `icon-composer.ts` (the `.icon` bundle; layers listed front to back, picket first), `text.ts` (JSON through Prettier's API, shared by the renderer and the golden test) and `render-assets.ts`, run by the bare script `"brand:render": "tsx scripts/brand/render-assets.ts"`. It screenshots SVG documents with Chromium from `@playwright/test` and writes `assets/brand/{mark-light,mark-dark,icon}.svg`, `assets/fencepost.icon/{icon.json,Assets/picket-f.svg,Assets/accent-rail.svg}`, `assets/images/{icon,favicon,android-icon-foreground,android-icon-monochrome,splash-icon,splash-icon-dark}.png`. A second run is byte-identical on the same machine; the committed files are the source of record and README says regeneration is a local step.
3. **`app.json`**: `ios.icon` -> `./assets/fencepost.icon`; `android.adaptiveIcon` -> foreground + monochrome + `backgroundColor: "#16211d"`, no `backgroundImage`; splash `backgroundColor: "#eef1ef"`, `image`, `imageWidth: 120`, `dark: { backgroundColor: "#16211d", image }`. `assets/expo.icon/` and `android-icon-background.png` deleted. The splash follows the system scheme, not "always chalkboard" (see the decision entry). A stray `android.package` written by the throwaway Android prebuild was removed at review.
4. **Tests** (all under `scripts/brand/`, where Node types exist): `palette.test.ts` (every hex in `app.json` is a palette value; the README palette table equals the palette), `svg.test.ts` (Android safe zone measured against the 66/108 circle), `icon-composer.test.ts` (`srgb` format and `#rrggbb` guard, picket listed first) and `golden.test.ts` (every committed vector and bundle file equals the renderer's output). The proposal first placed the palette test under `src/theme/`; see the knowledge entry on `node:fs` tests.
5. **In-app**: `BrandMark` with `testID="brand-mark"` on a wrapping `YStack` (react-native-svg drops `testID` on web) and `aria-hidden`; the topics sheet title is mark + the unchanged "Fencepost" text; the e2e starter spec asserts both are visible.
6. **Docs**: README "Theme and brand" (palette table, type faces, dot grid, the mark, asset inventory, `npm run brand:render`); `src/theme/colors.ts` points at it; NOTES.md names the asset-change build path and the remove-`ios.icon` recovery.
7. **Verification done**: throwaway iOS and Android prebuilds; `xcrun actool` (Xcode 26.2) on the real catalog with the bundle, zero errors and warnings, emitted `60x60@2x` viewed twice (before and after the layer-order fix); `sips -g hasAlpha icon.png`: no; `npm run guard` exit 0 (193 tests); `npm run e2e` 14 passed. Residual risk accepted: EAS builds with Xcode 27.1.

### Candidates considered
Criteria: (1) assets derive from the documented palette; (2) anyone can regenerate them; (3) no guarded path is touched; (4) smallest tooling surface; (5) the native config is verified before merge, since CI can't.

- **A (recommended). One geometry module + a Chromium renderer from `@playwright/test`, outputs committed.** Meets 1, 2, 3, 5. Costs one script of roughly 150 lines plus small helpers and one npm script (criterion 4). Determinism is local only (above).
- **A'. Same, rendering with `@resvg/resvg-js` or `sharp`.** Deterministic across platforms and no browser launch, but a new native devDependency (lockfile, osv-scanner, `expo install --check`), against criterion 4. Rejected for this unit; noted in README as the upgrade if cross-machine drift ever matters.
- **B. Hand-export the PNGs once, commit them, no script.** Meets 3, 4, 5. Fails 1 and 2: the palette and the rasters drift silently and the next change is done by hand.
- **C. A config plugin rendering at prebuild time.** Meets 1 and 2 but adds a dangerous mod to every prebuild and the committed repo never shows the icon; worst on 4 and 5.

Why A over B: the user asked for the theme to be the documented source of the brand, which B can't honour; A uses only existing devDependencies.

### Out of scope
Android package id and Play assets, App Store screenshots, the display name, any `.github/`, `AGENTS.md`, `knip.json` or tsconfig edit, an EAS build before merge, the welcome-card eyebrow, web manifest or apple-touch-icon (`web.output: server` uses only the favicon).

## Success criteria
1. `assets/expo.icon/` and `assets/images/android-icon-background.png` are deleted; `git grep -il "expo-symbol\|grid.png" -- assets app.json` returns nothing; every file under `assets/` is written by the renderer.
2. `npm run brand:render` runs from a clean checkout and writes every raster, the SVG outputs and the `.icon` bundle; a second run on the same machine leaves `git status --porcelain` empty. README states this is a local, manual step and that Chromium output can differ across machines.
3. `app.json` references `./assets/fencepost.icon`, both splash images with a `dark` block, the adaptive icon foreground + monochrome + `backgroundColor` and no `backgroundImage`, and the favicon; `scripts/brand/palette.test.ts` passes, asserting every hex in `app.json` is a palette value and that the README palette table rows match the palette's tokens and values exactly.
4. Throwaway iOS and Android prebuilds succeed; `xcrun actool` compiles the real generated iOS catalog with the `.icon` bundle with zero errors and zero warnings; the emitted `60x60@2x` PNG was viewed and shows the mark; `sips -g hasAlpha assets/images/icon.png` is recorded in the scratchpad; the Android `res/mipmap-*` hold generated launcher PNGs. Nothing generated is committed. If the fallback fired, `ios.icon` is absent and the proposal says why.
5. `src/components/ui/brand-mark.tsx` exists, imports geometry only from `src/theme/brand-mark.ts` (the renderer imports the same module; jscpd reports 0%), and the e2e starter spec asserts `brand-mark` and the "Fencepost" title are visible in the open topics sheet; `npm run e2e` passes.
6. README has the "Theme and brand" section described in Approach 6, `src/theme/colors.ts` points at it, NOTES.md "Day to day" names the asset-change build path, and NOTES.md "When something goes wrong" names the remove-`ios.icon` recovery.
7. `npm run guard` exits 0 and `git diff --name-only main...HEAD` contains no path listed in `.github/guardrail-paths.txt`.
